# Nano clause-selection evaluation

Measured in real desktop Chrome (a dedicated profile, Gemini Nano on-device through Firebase AI Logic `ONLY_ON_DEVICE`) using the sample contract (16 clauses). Each task was asked through the real UI and the request was then denied, so nothing was sent to the cloud. Generated by `node scripts/eval-nano.mjs`.

## Reading these numbers

- Recall is the share of clauses a careful reader needs that the model kept. A miss means the cloud answer may lack a passage it needed.
- Precision is the share of kept clauses that were needed. Lower precision means more of the document was disclosed than necessary, but the policy engine still masks sensitive values in every kept clause.
- Nano is not deterministic, so repeated runs can differ. Selection is only a proposal: code decides what may leave.
- The first call after a page load includes model warm-up time.
